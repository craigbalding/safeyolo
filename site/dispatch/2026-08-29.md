### Freeze proposal text with the revision that selected it

**Attribution:** Independent review finding (Lens)

```python
if current.status is ProposalStatus.PROPOSAL_READY and updated.revision == current.revision:
    updated = replace(current, first_seen=min(current.first_seen, seen_at), last_seen=max(current.last_seen, seen_at))
```

SafeYolo increments a proposal's semantic revision when evidence changes the proposal's meaning. Independent review found that later, nonmaterial metadata could change the displayed text without advancing that revision. The final proposal record now freezes the selected text; only material evidence creates a new revision.

**Lesson:** The revision used for deduplication and the text selected for display must advance together. Otherwise, replay protection can still publish contradictory text.

**Evidence:** [Reviewed implementation in PR #446](https://github.com/craigbalding/safeyolo/pull/446), [Frozen-body and replay regressions](https://github.com/craigbalding/safeyolo/blob/dd5201b92f8d9b6b4708f4750b8f3cc3d81f5142/cli/tests/test_coord_factory_proposals.py#L309-L452)

## Worth knowing

### A process lock conflicted with SQLite on macOS

**Attribution:** Infrastructure or environment finding

SafeYolo's Mattermost adapter uses SQLite to remember processed messages, prevent replay, and match operator buttons to requests. A separate process lease ensures that only one adapter updates this state. Locking the database file itself passed Linux-heavy tests but conflicted with SQLite's own locks on macOS, so the lease moved to a sibling file. Real-macOS acceptance then found another platform assumption: the adapter had to verify the identity of a /dev/fd descriptor and resolve it to a normal filesystem path before SQLite could create its write-ahead-log and shared-memory files. The operator's future direction is sandboxed macOS acceptance for ground-truth platform testing; SafeYolo does not ship that capability today.

**Evidence:** [Live-trial report on issue #442](https://github.com/craigbalding/safeyolo/issues/442#issuecomment-5462519079), [Corrective PR #448](https://github.com/craigbalding/safeyolo/pull/448), [Real-macOS acceptance correction PR #452](https://github.com/craigbalding/safeyolo/pull/452), [Operator-informed Dispatch issue #454](https://github.com/craigbalding/safeyolo/issues/454)
