### Freeze the proposal body with its semantic revision

**Attribution:** Independent review finding (Lens)

```python
if current.status is ProposalStatus.PROPOSAL_READY and updated.revision == current.revision:
    updated = replace(current, first_seen=min(current.first_seen, seen_at), last_seen=max(current.last_seen, seen_at))
```

Independent review found that non-material metadata arriving after a proposal became ready could change its presentation without changing the semantic revision. The final ledger preserves the selected body until material evidence creates a new revision.

**Lesson:** A deduplication key and the bytes selected for presentation must advance together; otherwise replay protection can still emit contradictory copy.

**Evidence:** [Reviewed implementation in PR #446](https://github.com/craigbalding/safeyolo/pull/446), [Frozen-body and replay regressions](https://github.com/craigbalding/safeyolo/blob/dd5201b92f8d9b6b4708f4750b8f3cc3d81f5142/cli/tests/test_coord_factory_proposals.py#L309-L452)

## Worth knowing

### Put process locks beside SQLite, not on it

**Attribution:** Infrastructure or environment finding

A live macOS trial exposed that taking a process-level flock on the SQLite database itself can conflict with SQLite's own file locking. The adapter now leases a private sibling .lock file and leaves the database inode to SQLite.

**Evidence:** [Live-trial report on issue #442](https://github.com/craigbalding/safeyolo/issues/442#issuecomment-5462519079), [Corrective PR #448](https://github.com/craigbalding/safeyolo/pull/448)
