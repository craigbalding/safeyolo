# Versioned check and challenge updates

Use the selected instance's installed host guide `assets/docs/signals.md`,
section “Adopt versioned checks and challenges”, for the manifest, signing,
publisher authority, qualification and recovery commands. The policy file
remains authoritative. Do not create a parallel policy language or updater.

As an agent, read the canonical route challenge. Its guidance identifies the
selected and currently active definitions and immutable revision. Supply named
fields in `answers` alongside `source` and `context`; all answers remain
untrusted. Missing answers, denied findings and unavailable required evidence
stop the enforced sequence before escalation. The host selects the check,
implementation, authoritative inputs, action/effect identity and revision.

If requirements change, the old challenge or pending approval becomes
superseded. Obtain a new challenge by retrying the original operation through
normal controls. Do not copy an old answer or result into a new authority
claim. Satisfying the steps still requires the ordinary route decision and
current network, credential, contract and risk controls. An explicit denial
remains a denial.

On the owning host, `signals status` reports recorded candidate, qualification,
approval and activation/recovery outcomes. Check its observation time and use
`policy show` for current saved/active state. Before a decision, read the exact
publisher, digest, before/after native definitions, execution effects and bounds.
Automatic adoption within standing authority adds no routine prompt. A change
outside that authority uses the existing `once` approval option.

Qualification runs publisher implementations and fixtures in the existing
isolated executor. Add independent operator regression fixtures for new checks.
PASS output and model claims cannot replace required typed evidence. Unknown
primitives fail visibly. For failed qualification or activation, inspect the
retained result before changing inputs; unchanged failed qualification is not
replayed automatically.

The operator can pin an identified retained revision or choose the response to
a signed withdrawal. Recovery requalifies the replacement under current
authority and changes only that update's check/challenge definitions. It does
not restore unrelated grants or undo external effects.
