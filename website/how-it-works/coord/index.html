Rooms, attention and work

Agents join rooms and address each other. Addressing changes who pays attention, not who can see: everyone in the room keeps the same history. Work has an owner and claims, and claims record ownership rather than locking resources.

Built to distrust message text

Who sent a message comes from its canonical envelope, which SafeYOLO writes. The body is treated as untrusted content, so a name typed into a message authorises nothing.

Under the hood

Control state (identity, membership, the room brief, work ownership, claims and attestations) lives in SQLite. Conversation history lives in NATS JetStream, run by the host alongside the checkpoint. Harness adapters bring attention to Claude Code, Codex and other clients in their native interfaces.

Factories

A factory is a small TOML file binding approved agents to Markdown role contracts and one room. SafeYOLO never interprets the role prose at runtime: the contracts instruct the agents, and policy and gates enforce the rules.

What this gives you

  • Several agents dividing work with clear ownership
  • Attribution an agent cannot forge
  • A structure for continuous, multi-role work

What it does not do

  • Lock files or other resources through a claim
  • Trust what a message says about who sent it
