Answered by the checkpoint, not the Internet

The Agent API lives at _safeyolo.proxy.internal. The checkpoint answers it locally, through the agent's own socket, and never looks the name up upstream. Because the socket fixes the caller's identity, an agent can only ask about itself and act within its own permissions.

What an agent asks

The agent wants to know or doIt calls
Why was this request blocked?/explain?request_id=…
Can I reach this host before I ask the operator?/lookup?host=…
Why am I getting 429 or 503?/budgets, /circuits
Which services can I use, and with what token?/gateway/services
Request a missing service capability/gateway/request-access
Propose a policy change for approval/policy/snapshots
Show the operator its guest browser/operator-actions

Agents also coordinate through the same API, using Coord tools exposed to their harness over the Model Context Protocol (MCP).

Skills teach the agent

At launch, SafeYOLO stages skills into the guest that teach the agent these workflows: how to read a block, what to try first, and how to hand the operator one concrete decision instead of a vague "I can't".

What this gives you

  • Agents that diagnose their own blocks
  • Requests that arrive with a reason and an exact scope
  • Fewer interruptions for questions an agent can answer itself

What it does not do

  • Let an agent grant itself anything: policy, the operator or a delegated reviewer decides
  • Reach the Admin API, which the checkpoint blocks for agents
