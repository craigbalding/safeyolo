A target that knows its limits

safeyolo-host-executor runs on the target: Linux, macOS or Windows. It needs no full SafeYOLO installation. The target enrols the issuing instance's keys, sets scope ceilings and budgets, and keeps a ledger of what ran.

Signed, bound and versioned

Under the safeyolo.host-execution/v1 contract, your SafeYOLO instance invokes adopted, versioned operations on a named target. Each request is bound to an authenticated agent run and an operator task you activated. The signing keys stay with your instance; the agent never holds them.

Contained on each platform

On Linux, operations run under bubblewrap, with selected writable paths and network authority. On macOS, they run under a Seatbelt profile that child processes inherit. On Windows, Job Objects bound memory, processes, output and time.

Agents can propose, owners adopt

An agent can prepare first trust and propose new task code. The target's owner and your policy qualify and adopt those changes. Discovery and proposals cannot raise a ceiling or enrol an issuer.

Platform qualification of this integration is tracked in #1669.

What this gives you

  • Real work on real machines, without SSH keys in a sandbox
  • Only the operations you adopted, within ceilings the target sets
  • A ledger on the target of what ran and for whom

What it does not do

  • Run arbitrary commands an agent makes up
  • Let a proposal widen its own authority
