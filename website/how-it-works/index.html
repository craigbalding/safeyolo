How it works

One checkpoint between your agents and everything else

Each agent works in its own sandbox. Its only route out is a socket into SafeYOLO, which decides every request against the policy you set. Select any part of the map to see what it does.

{% include map.html %}

The parts

Agent sandboxIts own Linux machine, root inside, no network interface. Agent APIHow an agent asks why it was blocked, and asks for more. CheckpointThe Rust proxy that decides every request and fails closed. Policy and approvalsDecide once; agents only ask about what is outside it. CredentialsAgents use your services; the secrets stay on your host. EvidenceEvery request, decision and reason on record. CoordRooms, work and claims for agents working together. GatesDeterministic checks the agents cannot skip. Remote machinesNamed, signed operations on other hosts, without SSH. Other SafeYOLOsConnect instances for support, approvals and federation.

Two rules hold everywhere

Identity comes from the socket, never from the request.

The socket a connection arrives on fixes which agent it is. Headers, JSON fields and bearer tokens cannot select another agent.

Fail closed.

Unknown credentials and out-of-policy requests get HTTP 428 (approval required) or 403 (denied), never silent passthrough. Policy is loaded and validated before any agent can connect.

Both rules assume a trusted host. If your host account or SafeYOLO's own directory is compromised, these protections do not hold.
