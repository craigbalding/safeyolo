Connected, not merged

Instances connect over NATS, secured with TLS and a selected certificate authority or with verified Tailscale. Broker and certificate authority private keys and Admin tokens stay on their own hosts, and every guest keeps using its own local Agent API. safeyolo configure guides the setup and gives the other side one scoped peer credential, which you transfer privately.

Agents that support other agents

An owner can grant a support agent, local or on another instance, specific powers over named target agents:

PermissionLets the support agent
InspectionRead the target's runtime, harness and proxy state
guest_logsRead selected paths inside the target
guest_adminRun commands inside the target guest to investigate and repair it
lifecycleStart, stop or restart the target's sandbox or harness
factory_directionsSend selected direction types to an approved factory

Approvals and notices across machines

Delegated reviewers can decide selected requests for named workers, and selected lifecycle and needs-operator events can be delivered to an authorised recipient.

What this gives you

  • One agent looking after others, across machines
  • Private keys and Admin tokens that never leave their hosts
  • Grants bound to durable identities, not names

What it does not do

  • Limit guest administration to less than the target itself can do
  • Transfer a grant to a new agent that reuses an old name
