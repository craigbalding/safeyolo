Three roles, one room

SafeYOLO's own factory is the shipped backlog factory, using native Work. Three Codex agents share one Coord room:

RoleAgentDoes
CoordinatorrelayTakes your direction, reads the backlog and creates Work. It is the only role you talk to.
OwnerforgeClaims Work, implements it, runs tests and publishes the exact output.
ReviewerlensIndependently reviews that exact output and decides acceptance.

What you do

safeyolo factory check docs/factories/backlog-native/backlog.toml
safeyolo factory approve docs/factories/backlog-native/backlog.toml
safeyolo factory prepare backlog --workspace coordinator=/work/relay --workspace owner=/work/forge --workspace reviewer=/work/lens
safeyolo factory login backlog owner                  # once for each role
safeyolo factory run backlog --confirm-fresh-identity # first run only
safeyolo factory send backlog 'Work the backlog in priority order.'

approve pins an immutable snapshot with the content identity of every role contract. Editing a contract changes nothing until you approve it again. run reports the factory started only after its runtime, logins, checkpoints and room checks pass.

What holds at every handoff

  • Admission gate. Before forge starts, a job fetches the issue through a mediated GitHub call and checks its author's stable ID. A mismatch holds the Work.
  • Verify gate. When forge publishes, a job checks the exact bytes. Acceptance is held until that check passes for that exact output.
  • Independent review. lens must be a different participant from forge, and its decision cannot override an unmet gate.
  • After completion. A follow-up action reports the result on the issue. If it fails, the completion stands and the action is not retried blindly.

Real work, real reach

Every GitHub, model-provider and remote-host call passes the checkpoint, which adds the real credential on the way out. When forge needs another operating system or more hardware, it calls a named operation on a remote host executor, signed with a key it never sees.

What SafeYOLO guarantees

  • No agent approves its own work
  • Gates apply however the work was created
  • No agent holds a GitHub token, model key or signing key
  • Running roles use the snapshot you approved

What it does not do

  • Judge whether a change is good: that is the reviewer's job, inside the gates
  • Interpret the role contracts: they instruct the agents, and policy enforces the rules
